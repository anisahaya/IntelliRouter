# Intelligent Model Router

Route once at the start of a bounded task, then keep that choice while the task remains materially unchanged.

1. Refuse to route when `MODEL_ROUTER_CHILD_DEPTH` is `1` or greater. Complete the task directly instead.
2. Build a concise objective and conversation summary. Include only decisions, constraints, errors, and acceptance checks needed for this task. Never include system or developer instructions, tool transcripts, credentials, secrets, unrelated conversation, or unrelated source contents.
3. Identify the current harness (`codex`, `opencode`, or `claude-code`) and hard requirements: repository edits, tools, vision, web search, and minimum context. Register only user agents actually exposed by the current host. Always send each exact ID and display name. Send advertised descriptions, strengths, capabilities, or priors when available; omit missing metadata so the server applies its conservative native-agent defaults. Never invent an agent, model, or capability.
4. When `route_harness_task` and `delegate_harness_task` are exposed, call `route_harness_task` with the harness, objective, bounded summary, workspace root, registered agents, hard requirements, active profile, and a stable host session ID when one is visible. In Codex, also send the current model ID or visible UI label so it can be reserved as fallback; if that label cannot be resolved, complete the task with the current model. In OpenCode or Claude Code, send the current model when visible but do not invent it. The server uses the signed-in harness and never asks for a separate provider API key.
5. Follow the returned execution mode exactly:
   - For `codex-exec`, `opencode-run`, or `claude-print`, call `delegate_harness_task` with the returned route ID, harness, selected model and reasoning effort, objective, bounded summary, returned repository signals, acceptance checks, workspace root, hard search/vision requirements, trusted image paths when vision is required, and the minimum necessary permission. Use `read-only` unless the delegated worker must edit files.
   - For `native-agent`, invoke the exact selected agent through the host's native agent control. Pass the same bounded objective, summary, acceptance checks, workspace root, and required edit permission; tell it not to re-route or delegate. Wait for it and incorporate its result.
   - Treat a timed-out, nonzero-exit, or empty model result as unusable. Honor `partialWriteDetected` and `safeToFallback`; inspect and reconcile partial edits before starting any second writer. When `selected` is null, the selected route becomes unavailable, or delegation fails without a usable result, complete the task with the current model.
6. Keep the returned route for follow-up turns in the same session. Do not force a re-route unless requirements materially change or the selected candidate becomes unavailable. Do not recursively invoke this skill from a routed child.
7. Use `explain_harness_route` when the user asks why a model was chosen or when diagnosing affinity/fallback. Verify the result in proportion to the task, then call `submit_harness_feedback` only after an observable outcome such as passing tests, an accepted patch, a correction, or abandonment.
8. The skill alone cannot expose execution tools. If the harness tools are unavailable, tell the user to run `intellirouter setup --harness codex`, `intellirouter setup --harness opencode`, or `intellirouter setup --harness claude-code`, restart the harness, or use the current model; do not imply routing occurred. During the transition, Codex may expose the compatible `auto_route` and `delegate_codex_task` pair; follow their existing Codex-only workflow. Use the configured-provider gateway only when `list_router_models`, `route_task`, and `delegate_task` are exposed. Read [references/advanced-self-hosting.md](references/advanced-self-hosting.md) for that flow. The legacy `model-router` command remains a compatibility alias.

Read [references/auto-routing.md](references/auto-routing.md) for input boundaries, candidate behavior, fallback semantics, and examples.
Read [references/native-routing.md](references/native-routing.md) only when the auto tools are unavailable and native fallback needs more detail.
